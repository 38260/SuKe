溯刻 · SuKe

Windows 11 工作区管理器。它恢复的不只是窗口矩形——还包含受支持的文件、文件夹、浏览器会话、资源管理器标签页、终端标签页，以及每个窗口所在的虚拟桌面。

当前版本 v1.7.0 — Desktop Context .NET 8 · C# 12 · WPF Windows x64 MIT License Release 测试 380 通过 / 0 失败

一句话：SuKe 是一个常驻托盘的 Windows 应用。你把当前正在用的一整套工作环境「拍一张快照」存成工作区，之后随时一键恢复——包括窗口在多显示器上的确切位置、打开的文件与文件夹、浏览器标签页、资源管理器标签页、终端标签页，以及它们各自所属的虚拟桌面。

它和 PowerToys Workspaces 有什么不同

两者都能保存窗口位置。SuKe 的差异点在于保留上下文，而不只是矩形：

保存的不只是坐标

把应用放置、受支持的文件、浏览器会话、资源管理器标签页、Windows 终端标签页与虚拟桌面归属一起写进同一份快照。

显示器变了也能对齐

分辨率、DPI、扩展坞或显示器集合变化时，从「精确像素」自动切换为「语义化布局」（左半屏、三分、居中……）并重新映射。

恢复前可复核

歧义匹配会先摆在你面前让你确认；同一个活动窗口绝不会被分配给两条保存记录（会话级一对一 HWND 归属不变式）。

破坏性操作可回滚

精确切换与撤销必须先落一份持久化检查点；关闭窗口只用正常关闭请求，绝不强杀进程。

核心能力

跨显示器保存/恢复

多显示器、多虚拟桌面统一建模；重建缺失桌面并把窗口送回原处。

会话级集成

Chromium/Firefox 浏览器会话、PWA、资源管理器多标签页、Windows 终端标签页、VS Code 工作区。

六种恢复模式

Repair Move Existing Resume Launch Fresh Exact Switch Preview Only

逐条目策略覆盖

强制复用、缺失则启动、总是新开、从不启动、从不关闭、切换期间忽略。

检查点与撤销

可选常规检查点 + 强制的切换/撤销检查点，支持「撤销的撤销」。

脱敏诊断

逐条目、逐动作的结果报告；导出时路径/标题/URL/工作区名/标识符/命令行全部脱敏。

临时显示恢复

扩展坞插拔或分辨率抖动稳定后，可选择「先询问 / 禁用 / 自动+检查点」恢复布局。

可移植传输

工作区可导出为「精确」或「可移植/脱敏」文件，导入总是创建独立副本、绝不覆盖。

确定性仿真

9 组合成装置可在不动真实桌面的前提下验证规划器行为，适合 CI。

一次「恢复」到底发生了什么

这是理解整个项目的关键链路。注意「观测 → 纯规划 → 用户审批 → 过期预检 → 变更执行 → 校验」被拆成了彼此独立的边界。

  1. 观测（只读）枚举活动窗口、显示器拓扑、资源可用性、浏览器会话能力——不做任何改动。
  2. 纯规划RestorePlanner 生成不可变的 RestorePlan：每个条目的候选评分、选中匹配、DPI 感知目标位置、要执行的动作、警告与阻断错误。
  3. 用户审批预览对话框只渲染计划的投影；歧义条目需要你选一个候选，取消勾选则从计划中派生掉该条目的动作。
  4. 检查点整个切换（含关闭阶段）被包在一个事务闸门里。Exact Switch 与 Undo 强制先落一份持久化检查点，失败则零变更。
  5. 过期预检执行前重新比对当前候选清单与预览、重新校验每个被引用的资源。状态变了就返回 StalePlan，绝不悄悄重规划。
  6. 变更执行五个固定阶段：预检 → 浏览器与启动 → 就绪关联（250ms 轮询 / 45s 超时）→ 放置校验（有界重试）→ 有序结果聚合。
  7. 校验与报告重新读取被分配 HWND 的边界/DWM 边框/ShowCmd/DPI，按目标 DPI 缩放的 8px 容差判定，必要时最多纠正两次。失败汇总为 CompletedWithFailures。
为什么这样拆？ 因为「恢复」本质上是一个会破坏用户桌面状态的破坏性操作。把纯决策与副作用严格分开之后，规划器可以被 9 组合成装置完全离线测试，而执行路径上的每一次变更都必须重新校验它要操作的对象。

会话集成：Windows 没给 API 的部分

Windows 本身没有通用的「会话恢复」API，所以 SuKe 用应用适配器补齐：

目标实现方式
Chromium 浏览器 / PWAManifest V3 扩展 + 原生消息（命名管道 SuKe.BrowserBridge），协议 v2
Firefox独立包 + 独立管道 SuKe.BrowserBridge.Firefox；持久化 MV2 后台页（MV3 事件页会在等待桌面端请求时卸载端口）
文件资源管理器标签页Shell.Application 自动化 + IShellBrowser，在单条专用 STA 线程上串行化；按多重集合消耗位置，只补缺失的标签页，不产生重复
Windows 终端标签页可访问性发现 + 可选的 PowerShell 提示符钩子（标题出现 [WA:...] 标记即生效）；单条 wt 命令恢复整套标签页
虚拟桌面只用有文档的 IVirtualDesktopManager 接口；从不创建/枚举/命名/切换桌面，失败降级为动作级 Skipped
ATLauncher / 打包应用 / Squirrel 更新专用适配器：通过稳定启动器启动；从 AppxManifest.xml 推导 PackageFamilyName!ApplicationId；只在 Squirrel 安装根内解析同类最高版本

安全与隐私

  • 密码管理器与隐私/无痕浏览器窗口默认排除。
  • 恢复计划在执行任何变更前重新校验窗口与启动目标；过期计划被拒绝而不会被静默重建。
  • 关闭窗口只用正常关闭请求（WM_CLOSE），绝不强制终止应用。
  • Exact Switch 与 Undo 强制要求持久化检查点；失败则桌面保持不变。
  • 诊断导出会脱敏路径（只留扩展名）、URL（只留 origin）、标题、工作区名、标识符（转确定性假名）与命令行。
  • 工作区数据默认只留在 %AppData%\SuKe，除非你显式导出。
  • 检查点采集不包含截图与文档内容。
已知限制：SuKe 无法通用地恢复「应用或 Windows 没有暴露」的内部状态——例如未保存的编辑器缓冲区、shell 历史、终端分屏窗格、任意对话框状态与专有项目状态。另外，以管理员权限运行的应用可能拒绝来自非提权应用的窗口几何变更（会被报告为非致命警告）。

构建、测试与运行

前置条件：.NET 8 SDK，Windows x64。所有命令在仓库根目录执行。

# 跑完整 Release 测试套件（默认不会移动或启动真实桌面窗口）
dotnet test SuKe.sln --configuration Release

# 只跑确定性的恢复仿真子集
dotnet test SuKe.sln --configuration Release --no-restore `
  --filter "FullyQualifiedName~RestoreSimulationTests"

# 发布为单个自包含 exe
dotnet publish src/SuKe/SuKe.csproj -c Release -r win-x64 `
  --self-contained true -p:PublishSingleFile=true -p:PublishReadyToRun=true

# 在不动桌面的前提下检查某个装置的规划结果（退出码 0 = 期望全部匹配）
dotnet .\src\SuKe\bin\Release\net8.0-windows\SuKe.dll `
  --simulate-restore .\tests\SuKe.Tests\Fixtures\restore-simulations\single-monitor.json

通过后可执行文件位于 src\SuKe\bin\Release\net8.0-windows\win-x64\publish\SuKe.exe。完整的打包与 Release 产物流程见 构建、测试与发布。
