# WA-006A 人工验证 —— 检查点与撤销

> 本文为 [docs/manual-verification-wa-006a.md](../manual-verification-wa-006a.md) 的中文翻译。界面元素名、工单编号与诊断触发器名保持原样；若中英文出现歧义，以英文原文为准。

请使用一次性的 Windows 测试会话。Exact Switch 会向目标工作区之外的窗口发送正常关闭请求；请先保存所有真实工作，并且只使用测试应用（例如若干个独立的记事本窗口）。**不要**在存在未保存文档的情况下使用本流程。

## 准备

1. 启动两个记事本窗口，分别命名为 **Baseline A** 与 **Baseline B**，各自打开一个互不相同、且已保存的测试文件。把它们放在明显不同的位置，并记录其位置与显示状态。
2. 在 SuKe Settings 中启用 **Checkpoint routine restores**。保存一个名为 **WA-006A Baseline** 的工作区，包含这两个窗口。
3. 移动 **Baseline A**，关闭 **Baseline B**，再打开第三个一次性记事本窗口并命名为 **Introduced**。保存第二个工作区，命名为 **WA-006A Target**，其中只包含被移动后的 A。

## 验证事务

1. 以 Resume 模式恢复 **WA-006A Baseline**。确认诊断结果在任何放置动作之前报告了一个已创建的 `Restore` 检查点，并确认两个基线窗口回到了其保存时的几何与显示状态。
2. 对 **WA-006A Target** 运行 **Exact Switch**。确认预览识别出了目标之外的窗口；批准之后，它们只收到正常关闭请求。确认诊断结果在关闭阶段之前报告了一个已创建的 `WorkspaceSwitch` 检查点。
3. 从托盘运行 **Undo Last Restore**。确认基线窗口回到其记录的几何与显示状态，且 **Introduced** 通过一次正常关闭请求被对账。确认诊断结果在其关闭阶段之前报告了一个已创建的 `Undo` 检查点。
4. 再次运行 **Undo Last Restore**。确认桌面回到 Target 的排布——这证明第一次 Undo 捕获了它所替换掉的那个状态。

## 记录结果

对每个操作使用 **Copy Last Restore Diagnostics**，并记录脱敏报告中的状态、检查点触发/状态，以及任何需要关注的条目。一次失败的检查点必须让桌面保持不变，并且不得移除此前健康的检查点。不要把截图或未脱敏的工作区数据放进检查点存储。

只有当全部四个操作都在真实 Windows 桌面上成功，或者每个例外都被连同其脱敏诊断与后续缺陷单一起记录时，才可把 WA-006A 标记为完成。
